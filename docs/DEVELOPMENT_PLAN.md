# v0.2.0 开发计划与任务分工

## 1. 版本目标

`v0.2.0` 的目标是把 `v0.1.0` 固定参数单发失效复飞 Demo 扩展为可由前端配置、可配平、可接入场景三模型的统一仿真服务。

本版本必须形成以下完整链路：

```text
前端选择场景并填写参数
    → 后端读取场景参数规范并校验
    → MATLAB/Simulink 完成初始状态配平
    → 后端自动选择已发布提示词
    → Dify Agent 调用 reset/step
    → 仿真、评估和结果查询
```

场景二“地面减速”继续保留接口，刹车动力学、刹车效率、能量和 VMCG 等定量指标不属于本版本范围。

## 2. 当前基线

`v0.1.0` 已实现：

- 场景一固定参数运行：500 ft 双发下降、300 ft 左发失效、200 ft 单发复飞、500 ft 完成。
- Dify Agent 应用 API 调用和工具回调。
- 场景提示词自动编译、候选生成、自动评估和回归门控。
- 单实例 MATLAB Engine/Simulink 串行仿真。
- 固定工况配平脚本和单发低层增稳器。

`v0.1.0` 尚未实现：

- 前端可配置的初始状态、事件高度、目标高度和环境参数。
- 面向运行请求的动态配平服务。
- 场景三地面动力学、轮胎侧向力和转向执行机构。
- 场景三提示词、评价器和回归样例。

## 3. 分工及目录边界

### 3.1 后端与算法负责人

负责范围：

- `src/multiflight/`
- `resources/scenes/`
- `resources/prompts/`
- `tests/`
- Dify Agent、任务理解、提示词选择与优化逻辑
- 参数校验、配平编排、运行任务和结果接口
- 前端与模型的最终集成

主要交付：

1. 场景参数 Schema 及参数间约束。
2. `prepare` 配平接口及配平结果缓存。
3. 参数化后的 `/api/runs`，运行记录必须保存实际参数和配平版本。
4. 场景三 Python 适配器、状态映射和评价器。
5. 自动化测试和接口文档。

### 3.2 Simulink 模型负责人

负责范围：

- `simulink/` 中的 `.slx` 模型和 MATLAB 入口脚本
- 场景三地面动力学、轮胎侧向力、前轮转向或等效转向执行机构
- 所有需要修改 `.slx` 的公共能力，例如真实风场输入端口
- 场景一动态配平所需 MATLAB 函数

主要交付：

1. 场景一参数化配平入口，并返回收敛状态、配平状态和配平控制量。
2. 场景三可独立运行的 reset/step 入口。
3. 场景三模型文件、默认工况、最小测试脚本和基准结果。
4. 输入输出字段、单位、范围和失败原因说明。
5. 不实现差动刹车，但保留 `brake_left`、`brake_right` 输入字段并明确忽略状态。

详细接口见 [SCENE3_MODEL_CONTRACT.md](SCENE3_MODEL_CONTRACT.md)。

### 3.3 前端负责人

负责范围：

- 调用后端公开 API，不直接调用 Dify 或 MATLAB。
- 根据后端参数 Schema 动态生成不同场景的表单。
- 展示参数校验、配平状态、任务进度、仿真结果和失败信息。
- 保存后端返回的 `preparation_id`、`run_id`，不得自行拼接提示词。

主要交付：

1. 场景选择页和参数表单。
2. 配平确认与错误展示。
3. 实验启动、进度轮询和结果展示。
4. 一套使用后端测试数据完成的演示流程。

详细接口见 [FRONTEND_API.md](FRONTEND_API.md)。

## 4. Git 分支和合并方式

```text
main
└── develop
    ├── feature/parameterized-simulation
    ├── feature/scene3-model
    └── feature/frontend-contract
```

- `main`：只接受已验收版本，禁止直接开发。
- `develop`：第二版集成分支。
- `feature/parameterized-simulation`：后端参数化、配平和提示词链路。
- `feature/scene3-model`：模型负责人独立开发场景三。
- 前端代码如果位于其他仓库，仍以 `FRONTEND_API.md` 的版本为集成依据。
- 模型分支不要修改 `src/multiflight/`；后端分支不要直接改场景三 `.slx`，避免二进制模型冲突。
- 每次合并必须附带测试结果和交付清单，不允许只提交模型文件而没有入口脚本。

## 5. 推荐开发顺序

### 阶段 A：冻结契约

1. 确认参数字段、单位、范围和字段间关系。
2. 确认场景三 MATLAB reset/step 输入输出。
3. 前端、后端、模型负责人共同确认契约版本为 `0.2.0-draft.1`。

### 阶段 B：并行开发

- 后端：参数 Schema、校验、配平任务和参数化运行。
- 模型：动态配平入口、场景三模型和真实风场输入。
- 前端：使用静态样例先完成表单、配平状态和运行进度页面。

### 阶段 C：第一次集成

1. 后端调用真实场景一配平入口。
2. 前端通过真实 API 跑通参数化场景一。
3. 后端用场景三默认工况调用模型 reset/step。
4. 统一错误码、状态字段和单位。

### 阶段 D：验收和发布

1. 执行单元测试、接口测试和真实 Simulink 冒烟测试。
2. 按 [ACCEPTANCE_CHECKLIST.md](ACCEPTANCE_CHECKLIST.md) 完成验收。
3. 合并到 `develop`，完整演示后合并到 `main`。
4. 创建 `v0.2.0` 标签并保存演示参数和结果。

## 6. v0.2.0 完成定义

只有同时满足以下条件才能发布：

- 场景一可以使用非默认合法参数完成“校验—配平—运行—结果查询”。
- 非法高度关系、超范围空速和配平不收敛均能在启动仿真前被拒绝。
- 运行结果能够追溯实际参数、配平结果、提示词版本和模型版本。
- 场景三默认工况能够经过统一 reset/step 接口运行，且输出横向偏差、航向误差和状态安全信息。
- 场景二仍明确返回不可运行，不得显示为已实现。
- 前端无需输入提示词，也不直接感知 Dify API Key。
- 自动化测试通过，真实 Simulink 演示可复现。
